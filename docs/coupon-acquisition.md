# 公式クーポンの取得方法（2026-11-01調査）

## 今回の結果

掲載数が少なかった主因は、手作業で選んだ少数の公式発表だけを使い、公開HTMLの商品別クーポンを収集していなかったこと。

- ファミマ「何度でも使えるクーポン」は、ログイン不要のHTMLに商品名、割引額、利用期間、地域条件がある。実ページを取得して14件を構造化できた。既存3件と合わせて17件。
- セブンの公開キャンペーンから、アロエヨーグルト40円引きとホットドリンク50円引きのレシート券を追加。購入条件と発券期間・利用期間を分けて保存。
- 飯田橋の掲載店舗に対応する情報は8件から24件。商品違いの券を分割して件数を水増しせず、公式の1クーポン枠で1件。
- ドトールの来店ポイントや抽選は値引き券ではないため、クーポンとして追加していない。

確認した各社ページに第三者向けの公開クーポンAPIの案内は見当たらなかった。「APIが存在しない」との断定ではない。

## 実装する順番

1. 公開HTMLを取得する収集器をチェーンごとに用意。検索結果の抜粋ではなく詳細ページを取得する。実際に同じファミマURLの検索抜粋は9月、直接取得したHTMLは10〜11月で、抜粋だけでは期限判定を誤る。
2. 画像/PDFにしかない発表はOCRで候補抽出し、商品・金額・期間・利用条件を確認してから登録。曖昧な期限や金額を補完して公開しない。
3. アプリ内限定の全券が必要なら、公式とのデータ連携を優先。暫定的には公式アプリ画面から商品・金額・期限を人が確認して登録する方式も選択肢。利用者個別の保有状況とは別データにする。
4. 品質を確認した収集器から、サーバー側（GitHub Actions等）で定期実行→検証→JSON/JSを生成→Pagesに反映する。ブラウザから各社サイトを直接取得する方式はCORSや可用性に依存するため採用しない。

## 今回の収集器

```
python3 scripts/collect-family-coupons.py
python3 -m unittest discover -s tests
```

`coupon-feed.js`を更新する。依存パッケージ・APIキー・ログイン不要。手動実行のみで、定期実行はまだ設定していない。

- HTMLの実データから商品・割引額・期限を取得。年は公式画像の年月パスから照合し、見つからなければ停止。
- 対象商品全種と商品別の地域条件を保持。取得日・出典URLを保存。
- 期限切れ除外、重複ID検査、HTML構造変更の検知、異常な期間の拒否。
- 取得や解析に失敗したときは既存のファイルを保持。成功時にまとめて置き換える。
- 公式画像やバーコードを複製せず、クーポンの内容を構造化して表示。利用には公式アプリや紙券が必要。

自動化を広げる際は、取得元ごとの利用条件・取得頻度を確認して設計する。
